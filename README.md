## 1. نظرة عامة ومواصفات المشروع (Overview & Architecture)

تم بناء وتطوير هذا المشروع وفق أعلى المعايير الهندسية في مسار **هندسة البيانات الضخمة (Enterprise Big Data Engineering)** ليكون حلاً مؤسسياً متكاملاً يعالج ويدير تدفقات طلبات التجارة الإلكترونية، حيث يدمج بسلاسة تامة بين مرحلتي التقييم:
* **المرحلة الأولى (المشروع النصفي):** خط أنابيب إدخال هجين فائق السرعة يعتمد معمارية **ELT Streaming**، مزود بموجه ملفات ذكي، و10 قواعد تصحيح آلي مع سجل أثر التدقيق الكامل (`corrections audit trail`)، و12 قاعدة عزل صارمة للشوائب، ونظام نقاط حفظ (`Checkpointing`) يمنع تكرار معالجة السجلات.
* **المرحلة الثانية (المشروع النهائي):** طبقة التحليلات المتقدمة والفهرسة المحسنة في **MongoDB**، تتضمن 4 فهارس إنتاجية تحقق خفضاً في مسح الوثائق يتجاوز **99.99%**، و5 استعلامات عملية ديناميكية، و5 خطوط تجميع إحصائي (`Aggregation Pipelines`)، وعروض مادية تُحدّث تزايدياً عبر `$merge` في أجزاء من الألف من الثانية، ومجدول مهام بالخلفية، ولوحة تحكم ويب تنفيذية ذات تصميم زجاجي فاخر (`Glassmorphism UI`) تدعم اللغتين العربية والإنجليزية.

   - تشغيل خط الإدخال والـ ELT بضغطة زر مع متابعة سجلات المخرجات الحية في الطرفية المدمجة.

### 4.1 معمارية خط الأنابيب (ELT) والتوجيه التلقائي للمحرك (File Router)

يعتمد النظام معمارية **Extract-Load-Transform (ELT)** الحديثة وفق المعايير السحابية:
1. **الاستخراج والتحميل الفوري (Extract & Load):** قراءة ملف CSV وتخزينه بالكامل في مجموعة `orders_raw` دون أي تعديل على محتواه الأصلي، مع إثرائه بـ 6 حقول بيانات وصفية للتدقيق (`Metadata`).
2. **التحويل وتطبيق الجودة (Transform in Database):** تطبيق قواعد الجودة والتنظيف والعزل، ثم كتابة السجلات الصالحة والمصححة إلى `orders_validated`، والسجلات التالفة إلى `orders_quarantine`.

```text
                                  ┌────────────────────────┐
                                  │   Incoming CSV File    │
                                  └───────────┬────────────┘
                                              │
                                              ▼
                             ┌─────────────────────────────────┐
```

### 4.4 الموثوقية وعدم التكرار (Idempotent Upsert & Schema Validation)

* **منع التكرار (Zero Duplicates Guarantee):**
  تم إنشاء فهرس فريد صارم على `order_id` في مجموعة `orders_validated`:
  ```python
  db["orders_validated"].create_index("order_id", unique=True)
  ```
  تتم الكتابة باستخدام عمليات `UpdateOne` مع تفعيل خيار `upsert=True`، مما يضمن أنه مهما تم تشغيل خط الأنابيب عدة مرات على نفس الملف، فإن عدد السجلات لن يتغير نهائياً ولن يتكرر أي سجل.
* **قواعد التحقق من البنية (Schema Validation):**
  تطبق قاعدة بيانات MongoDB عبر `$jsonSchema` قيوداً صارمة تمنع قبول أي وثيقة تفتقر للحقول الإلزامية (`order_id`, `customer_id`, `city`, `order_date`, `status`).

<a id="ar-4-6"></a>
### 4.6 إثبات معادلة الاتساق الأساسية (Consistency Equation Proof)

وفقاً للمعايير الصارمة لورقة تقييم جامعة الرازي، يجب أن يتحقق التطابق الحسابي التام:

$$\text{Total Read} = \text{Validated} + \text{Quarantined}$$

$$\text{Validated} = \text{Valid (Clean)} + \text{Corrected}$$

#### نتائج التشغيل الفعلي لملف الاختبار المعتمد (`20,000` سجل):
* **إجمالي السجلات المقروءة (Total Read):** `20,000`
* **السجلات المقبولة (Validated):** `17,000` سجل (بنسبة 85.0%)
  - سجلات سليمة تماماً من المصدر (Valid): `12,000` سجل.
  - سجلات تم تصحيحها آلياً وتوثيق أثرها (Corrected): `5,000` سجل.
* **السجلات المعزولة للشوائب (Quarantined):** `3,000` سجل (بنسبة 15.0%)
* **التحقق الحسابي:**
  $$12,000 + 5,000 + 3,000 = 20,000 \quad \checkmark \text{ (Matched 100\%)}$$
* **معدل التكرار (Duplicates):** `0` سجلات مكررة.

## 7. 🛠️ دليل استكشاف الأخطاء الشائعة وحلها (Troubleshooting Guide)

### ❓ المشكلة 1: خطأ الاتصال بقاعدة البيانات `ServerSelectionTimeoutError`
* **السبب:** خدمة MongoDB متوقفة على نظام Windows.
* **الحل:** افتح نافذة PowerShell بصلاحيات المسؤول ونفّذ:
  ```powershell
  net start MongoDB
  ```

### ❓ المشكلة 2: المنفذ 8000 مشغول مسبقاً `Address already in use`
* **السبب:** وجود نسخة سابقة من الخادم تعمل في الخلفية.
* **الحل:** إغلاق العملية السابقة أو تشغيل الخادم على منفذ بديل:
  ```bash
  python -m uvicorn src.api:app --host 127.0.0.1 --port 8080 --reload
  ```

### ❓ المشكلة 3: الاستعلامات تُرجع 0 سجلات في الواجهة
* **السبب:** تمرير نص عنصر الاختيار كاسم للمدينة أو تاريخ خارج نطاق عينة البيانات (بيانات العينة تقع في عام 2026).
* **الحل:** تم حل هذا الخلل تماماً في محرك الاستعلامات الديناميكي في `src/analytics_queries.py` و `dashboard.js`؛ حيث يضبط النظام تلقائياً التواريخ الافتراضية الصحيحة (`2026-01-01` إلى `2026-06-30`) وينظف المدخلات.

## 8. 🎙️ سيناريو العرض والمناقشة الشامل أمام لجنة التقييم (Defense Walkthrough)

لتقديم عرض متميز ومبهر خلال 10 دقائق أمام أستاذ المادة (م. عمر أبوسند):

### 🎙️ الدقائق 1 - 5: مناقشة المشروع النصفي (Phase 1):
1. **الخطوة 1 (موجه الملفات والمحرك الهجين):** افتح الطرفية ونفذ أمر الفحص الآلي:
   ```bash
   python verify_all.py
   ```
   اشرح للأستاذ كيف يقوم `file_router.py` بفحص الحجم الفيزيائي وتوجيه الملفات الأقل من 400MB إلى محرك `Python Batch Loader` فائق السرعة، ومبررات تجنب عبء تشغيل Spark للملفات الصغيرة.
2. **الخطوة 2 (التحميل الخام وجودة البيانات):** افتح برنامج **MongoDB Compass** على قاعدة `hamza_db`، واستعرض مجموعة `orders_raw` لتأكيد وجود السجلات العشرين ألف كاملة بحقول التتبع الستة.
3. **الخطوة 3 (سجل أثر التعديل والعزل):** افتح وثيقة من `orders_validated` واعرض مصفوفة `corrections` التي تثبت تصحيح الأرقام المشرقية أو توحيد التواريخ بدقة. ثم استعرض `orders_quarantine` واعرض السجلات المعزولة مع حقل `error_codes`.
4. **الخطوة 4 (معادلة الاتساق وعدم التكرار):** افتح ملف `reports/results.json` واستعرض التحقق الرياضي الدقيق:
   $$12,000 + 5,000 + 3,000 = 20,000 \quad (0 \text{ Duplicates})$$

### 🎙️ الدقائق 6 - 10: مناقشة المشروع النهائي (Phase 2):
1. **الخطوة 1 (اللوحة التنفيذية الفاخرة):** شغّل `run_api.bat` أو افتح المتصفح على:
   `http://127.0.0.1:8000/dashboard`
   استعرض التصميم الزجاجي، واضغط زر تبديل اللغة لإبهار اللجنة بالتحول السلس بين **العربية (RTL)** و **الإنجليزية (LTR)**.
2. **الخطوة 2 (الفهارس وتحليل Explain):** انتقل لصفحة الفهارس واضغط "تشغيل اختبار Explain"، واعرض بالأرقام كيف تحول المسار من `COLLSCAN` إلى `IXSCAN` مع انخفاض مسح الوثائق بنسبة **99.99%** للعملاء و **85.74%** للمدن والتواريخ.
3. **الخطوة 3 (الاستعلامات الخمسة الديناميكية):** استخدم أزرار التشغيل السريع (Quick Chips) لتنفيذ الاستعلامات الخمسة واستعراض جداول النتائج اللحظية بالريال اليمني وتفاصيل الفهرس المستخدم.
4. **الخطوة 4 (تقارير التجميعات والعروض المادية):** استعرض تقارير التجميعات الخمسة (المدن، المنتجات، كبار العملاء، الفترات، الحالات). ثم اضغط على زر "تحديث تزايدي" للعروض المادية لإظهار اكتمال العملية في **0.001 ثانية**.
5. **الخطوة 5 (خاتمة العرض وتوثيق Swagger):** استعرض توثيق Swagger التفاعلي عبر `/docs` واختم العرض بتقرير النجاح الكامل لسكربت `verify_all.py` بنسبة **100% (Grade: 7.0 / 7.0)**.
